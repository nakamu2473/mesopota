# 楔形文字手書きアプリ 設計メモ v0.1

作成日: 2026-08-03
コンセプト（2026-03の構想より）: 「表示できる」ではなく「**楔を押す方向と順番で書ける**」を再現する

## 0. 前提と現状
- 書き順はまだ講座で習っていない → **書き順の正解データは後から差し込める設計にする**（今は作らない・決め打ちしない）
- まずは「ドラッグで楔が打てる」体験の成立が最優先
- ターゲット環境: スマホ/タブレットのタッチ + PCマウス（Pointer Events で統一）

## 1. フェーズ分割

| Phase | ゴール | 状態 |
|---|---|---|
| P1 | ドラッグ1回 → 楔1つが描画される | ★今夜ここまで |

## 2. 楔（ストローク）のモデル

### 2.1 楔の種類（基本4分類）
実物の楔形文字の構成要素はほぼこの4種で説明できる:

1. **縦楔** (vertical): 上から下へ打つ。頭（三角）が上、尾が下
2. **横楔** (horizontal): 左から右へ打つ。頭が左、尾が右
3. **斜め楔** (oblique): 左上→右下 など斜め方向
4. **ウィンケルハーケン** (Winkelhaken): 尾のない「く」の字型の頭だけの楔。短いタップ〜ごく短いドラッグで打つ

### 2.2 データ構造
```
Stroke {
  type: "vertical" | "horizontal" | "oblique" | "winkelhaken",
  x, y: 開始点（頭の位置）,
  angle: 実測角度（deg）,
  length: 実測長さ（px）,
  order: 打った順番（連番）,
  timestamp
}

Glyph {
  strokes: Stroke[],
  targetChar?: string   // P3以降: 対応するUnicode文字
}
```
- order と angle を生データで保持しておくのがポイント。P4で書き順判定を足すとき、**過去の練習データもそのまま採点対象にできる**

## 3. 入力判定ロジック（P1の核）

### 3.1 イベント
- pointerdown: 開始点記録（= 楔の頭の位置）
- pointermove: プレビュー描画（任意）
- pointerup: ベクトル確定 → 楔1つ生成

### 3.2 分類ルール（初期値。あとで調整前提）
```
dx = endX - startX, dy = endY - startY
len = sqrt(dx² + dy²)
angle = atan2(dy, dx)  // deg換算

if len < TAP_THRESHOLD (例: 15px):
    → winkelhaken
else:
    angleを45度刻みで丸めて:
      -22.5°〜22.5°   → horizontal（右向き）
      67.5°〜112.5°   → vertical（下向き）
      22.5°〜67.5°    → oblique（右下）
      それ以外        → 一旦 oblique 扱い or 無効
```
- 実物の楔は基本「左→右」「上→下」「左上→右下」方向にしか打たない（葦ペンの持ち方の制約）
- **逆方向（右→左、下→上）のドラッグは「無効」として弾く**のを最初から入れると、書字方向の身体感覚がアプリに宿る。P1では警告表示だけでもOK

### 3.3 楔の描画
- SVG推奨（拡大縮小・書き出しが楽。Canvasでも可）
- 楔1つ = 「三角形の頭 + 細い尾」
  - 頭: 開始点に置く二等辺三角形（進行方向を向く）。サイズはlenに応じて微調整 or 固定
  - 尾: 頭の先端から進行方向へ伸びる細長い三角形（先細り）
  - winkelhaken: 頭のみ・尾なし（「く」の字。三角2辺で表現）
- 色: 粘土色背景 (#c8a878系) に 影付き刻み表現は P5。P1は単色シルエットで十分

## 4. P2: 文字キャンバス
- 1グリフ = 正方形キャンバス（例: 300x300）
- 機能: undo（最後の楔を削除）/ 全クリア / 楔リスト表示（順番つき）
- Glyphの JSON書き出し・読み込み（自分の書いた字を保存 → 後の正解データ作りの素材になる）

## 5. P3: 練習モード（お手本比較）
- Unicode楔形文字ブロック: U+12000〜U+123FF（シュメール・アッカド文字）ほか
- フォント: **Noto Sans Cuneiform**（Google Fonts / ローカル読み込み）
- UI: 左にお手本グリフ（薄く背景表示も可）、右に手書きキャンバス
- この段階では自動採点しない。目視比較のみ（採点はP4）
- 出題リスト: 講座で習った文字から手入力で追加していく方式（最初は10字もあれば十分）

## 6. P4: 書き順判定（講座で習ってから設計確定）
- 正解データ: `targetChar` ごとに `Stroke[]`（type + 相対位置 + order）を登録
- 判定: 打たれた楔列と正解列を order 順に突き合わせ
  - type一致 + 位置の許容誤差内 → ○
  - 順番違い / type違い を区別してフィードバック
- **正解データの作成ツール = P2のキャンバスそのもの**（自分で正しく書いてJSON保存 → 正解として登録）。専用エディタを別に作らなくて済む設計
